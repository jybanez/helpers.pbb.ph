Markdown Viewer

A complete file-viewing workflow, using canonical Helper components from open to close.

Full canonical Markdown formatting: headings, tables, lists and code. HTML is literal text, images never load, unsafe links are removed. Preview limit: 256 KiB.

Complete API and integration reference

Try the viewer

Integration

const createViewer = await uiLoader.get("ui.markdown.viewer");
const viewer = createViewer({ title: "Project file", url: fileUrl });
viewer.open(); // Visible loading before fetch starts.
// Reuse after the user selects another file:
viewer.update({ url: nextFileUrl });
// Or supply text already loaded by your application:
viewer.update({ content: sourceText, sourceUrl: downloadUrl });
await viewer.close();
viewer.destroy(); // Abort pending reads and release listeners.

For the bundle use dist/helpers.ui.bundle.min.js?v=0.21.223. Preload the factory during application initialization so a click can open its modal immediately.

States and lifecycle

  • URL reads show loading with a working close button, Escape and backdrop cancellation.
  • Empty files have an explicit message. Invalid files show the parse problem. Fetch failures include a Retry control.
  • Retry repeats only a read. Closing, destroying or selecting another source aborts reads and ignores late results.
  • Open source and Download preserve the original URL. Cross-origin download behavior depends on the server and browser.
  • Fullscreen uses the modal's viewport layout. Tab stays inside the dialog; closing restores the opener's focus.

Developer reference

content and url are mutually exclusive. Content is text, not HTML or a parsed object. Updating one clears the other. sourceUrl supplies optional source links for loaded content. limits can lower the documented budgets. Invalid options throw before changing the current viewer.

getState() reports format, open, destroyed, status, error, rowCount, fullscreen. Status is idle, loading, ready, empty, parse-error, fetch-error or destroyed. Reload an open URL viewer with reload().

Files use UTF-8 (optional BOM), HTTP(S) or caller-owned blob URLs. Same-origin credentials are used; cross-origin URLs require CORS. Server authorization remains the application's responsibility. This viewer never edits files or interprets spreadsheet formulas.
