The upload queue accepts status (queued, uploading, uploaded, failed), progress (0–100), optional progressLabel and errorText per item. Images/videos show an overlay bar; audio and other files show a bar below their content. Upload transport belongs to your application.

function onUploadProgress(id, loaded, total) {
  queueItems = queueItems.map(item => item.id === id ? {
    ...item, status: 'uploading',
    progress: total > 0 ? Math.min(100, loaded / total * 100) : undefined,
    progressLabel: total > 0 ? `${Math.round(loaded / total * 100)}%` : 'Uploading…'
  } : item);
  queue.setItems(queueItems);
}
// Call from your transport's progress events (e.g. XMLHttpRequest.upload).
// Mark uploaded only after confirmed server success; 100% sent is not confirmation.
// On failure set status:'failed' and errorText with an actionable message.

Progress/status updates retain the shared progress component and audio playback. Changing attachment contents recreates previews. The simulation is visual only and does not send requests.

Configuration reference

      
attachments chooses buttons and their order. Use singular video/audio here, but plural videos/audios in attachmentOptions. Settings alone never enable a button. emoji/emojis is reserved and does nothing yet.

      
    
        
  • attachments: []: no attachment buttons or file paste. An explicit list uses the helper row and takes precedence over showAttachmentButton. Duplicate names collapse; unknown names are ignored.
    • 
        
  • Omitted attachments: existing file-picker behavior using showAttachmentButton and attachmentPlacement.
    • 
        
  • files: accept (MIME types/extensions), multiple (default true), capture (native input hint), attachmentAdapter (native/custom/none). Falls back to existing top-level file options. A file filter does not restrict audio/video recordings.
    • 
        
  • videos and audios: maxBytes (default 25 MiB), maxDurationMs (default 60,000), mimeTypes (ordered supported recording formats), accept (final File filter, falling back to top-level accept). Exceeding a recording limit discards the clip; no truncated clip is attached.
    • 
        
  • audios.audioGraphOptions: style, sensitivity, gateThreshold, attackMs, releaseMs, intensityCurve, freezeOnPause, transparentBackground, className and ariaLabel. Recorder retains source, cleanup and no-header/no-mute layout ownership.
    • 
      

      
Graph defaults: classic-waveform, sensitivity 3.4, gateThreshold 0.06, attackMs 45, releaseMs 260, intensityCurve 1.7, freezeOnPause true, transparentBackground true. The graph responds to live input; stopped playback uses the native audio controls.

      
update({}, options) merges top-level options only. Pass the complete attachmentOptions object when changing one nested setting. On screens ≤600px, attachment labels hide while accessible names and touch targets remain.

    

    

      
Draft ownership, limits and cleanup

      
getAttachmentPolicy() synchronously returns current maxAttachments, attachmentCount, maxFileBytes, maxTotalBytes and usedBytes. Counts and byte totals must describe your current queue. Recording allowance is checked before opening and again before adding the File. The demo's 6 files / 20 MiB total and 10 MiB per recording are example limits, not production policy.

      
Validate every picker/paste/recording result before changing the queue. Server authorization, MIME/content checks and size limits remain mandatory. The Helper does not upload or retry mutations. Use effective server admission policy, not a storage ceiling.

async onSend({ text }) {
  if (!validateDraft(text, draftFiles)) return;
  composer.setBusy(true);
  try {
    await sendDraft(text, draftFiles); // App transport, confirmed success only.
    composer.clear();
    clearDraftFiles();
  } catch (error) {
    showSendError(error); // Preserve draft; do not automatically replay.
  } finally {
    composer.setBusy(false);
  }
}

      
The send snippet is integration pseudocode: supply your own validation, transport and error handlers. Set allowAttachmentOnly:true and call setAttachmentCount(count) with the number of validated attachments whenever your app-owned queue changes. Send then accepts text OR a positive count; whitespace with zero attachments is rejected. The default remains text-required. The count does not replace attachment/type/size/server validation, and onSend({text}) retains its existing shape; read your ordered queue in that callback. Busy state is app-controlled, not automatically inferred from the returned promise.

      
update(), setBusy(true) and destroy() cancel pending capture/picker work and ignore late results. Stopping or closing recording releases owned device tracks and analysis resources. clear() clears text only. Destroy the composer and revoke your queue's preview URLs when the view is disposed.

      
Audio queue items with a previewUrl show the Helper audio player with play/pause icons and smooth seeking progress. Without a preview URL they retain the filename fallback. Your app owns and revokes the URL; removing or updating the queue stops playback.
Video queue items use previewUrl for the playable video URL. The media strip shows its first frame automatically; optional thumbUrl/posterUrl must point to an image, never the video file. The play icon remains available if the browser cannot decode a preview.
For repository-backed selection, use attachmentOptions.files.attachmentAdapter: { mode: 'custom', open: async ({ signal }) => records } and onAttachmentsSelected. Return null/[] on cancel; records require id and name. See Repository Picker demo.
