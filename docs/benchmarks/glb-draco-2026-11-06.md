## Implementation boundary

The standard Three DRACOLoader lacks pending-promise rejection on disposal,
accessor/decoded-count reconciliation, and a native heap ceiling. A narrow adapter
retains GLTFLoader's canonical scene/material path while supplying those checks.
Only the pinned WASM decoder is used, with its memory maximum reproducibly reduced
to 128 MiB. A unit test grows the exported memory to that maximum and verifies
one additional page fails. This bounds decoder linear memory, not total process
memory: JS output, source copies, textures, GPU buffers and browser overhead are
additional. Aggregate output is capped at 128 MiB before JS output copies, declared
accessor accounting remains conservative, and loaded scene work is checked before
renderer creation. No decoded texture budget change is included here.

Workers are serialized within each viewer and limited to two concurrent workers
per runtime module/realm. Abort/error/deadline settle pending jobs and terminate
the worker. The 60-second deadline includes startup and queue time. No cross-tab
aggregate guarantee is claimed. CSP must allow same-origin worker/script/connect
requests and WebAssembly compilation. Unsupported compressed primitive forms are
listed in the component contract.

## Verification

- Synthetic Draco cube: source and main bundle, 1200px desktop and 375px/CPU4;
  three open/render/wireframe/close cycles per mode, non-background pixels,
  camera preservation, lost WebGL context and zero live workers after close.
- Close during decoding: pending worker terminated, no late canvas.
- Corrupt compressed bytes and false declared accessor count: error before render,
  worker terminated. Original private scene: expected workload rejection before
  worker construction in all four canonical modes.
- Unit controls: malformed view mapping, cyclic/expanded scene limits, actual WASM
  maximum, third simultaneous decoder rejection, abort and deadline settlement.
- Existing GLB source/bundle desktop/mobile suite, geometry/sparse/URI/required
  extension controls, pivot/wireframe regressions, registry and bundle contracts.

Early development runs caught an over-limit private fixture and an incorrect
upstream WASM filename mapping; both are represented by final regression coverage.
The final suite has no ignored failures.

## Isolated full-scene diagnostic

`tests/glb.draco.diagnostic.setup.mjs` writes only under `output/glb-draco/`.
It builds detached copies with 2,048 draws / 3M triangles for measurement while
retaining the 128 MiB geometry, decoded output and native decoder heap limits.
These relaxed guards are not in production sources, vendor assets or main bundle.

On Windows Chrome with actual Intel UHD D3D11 hardware rendering:

| Mode | Open-to-ready, three cycles | Wireframe toggle + GPU finish | Orbit action + GPU finish |
| --- | --- | --- | --- |
| 1200×800 desktop | 4.59 / 3.58 / 3.32 s | 33.8–57.1 ms | 20.1–54.8 ms |
| 375×800, CDP CPU4 | 4.28 / 3.74 / 3.72 s | 41.6–58.4 ms | 23.2–93.8 ms |

Both modes produced varied scene pixels, retained camera through wireframe,
terminated workers after parsing, lost contexts on all three closes, and cancelled
a subsequent in-flight decode without late rendering. Raw measurements are in
`glb-draco-2026-11-06-results.json`. The harness issues `gl.finish()` for control
samples; these few samples are not FPS/p95 or leak-freedom claims. CPU4 is a CDP
throttle on the test browser, not proof of worker throttling or constrained-memory
hardware. No native memory peak/VRAM measurement or real low-memory device result
is available. Decoder linear-memory enforcement is tested separately above.

## Reproduce

Run `npm ci`, `node scripts/build.glb.runtime.mjs`, `npm run build:ui-bundle`,
`node tests/glb.draco.setup.mjs`, and `node tests/glb.draco.unit.mjs`.
Place the authorized private GLB (exact hash above) at
`output/draco-assembled-private.glb`; do not commit it. Then run
`node tests/glb.draco.regression.mjs`. For diagnostic evidence, first run
`node tests/glb.draco.diagnostic.setup.mjs`, set `GLB_DRACO_DIAGNOSTIC=1`, then run
the same browser runner. Unset that environment variable for canonical tests.
