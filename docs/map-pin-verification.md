# Pin verification (task 267)

The complete canonical drawing adapter/tools and renderer APIs were inspected first. The existing adapter supplies placement, selection, pointer capture, editor modes, history, transactional colors, guarded deletion and metadata validation; Pin extends those paths. The verified rendering gap was actual fixed-screen 3D geometry and reusable read-only display, supplied by the new canonical `createMapPinRenderer` custom layer. No external model/texture/Three.js dependency, app renderer, app drag wiring or modular fallback was introduced.

`tests/map.pin.regression.mjs` uses Playwright CLI native desktop mouse input and a fresh 375px Chromium context with CDP touch input. Source and bundle runs cover Pin placement, native head selection, browser color/opacity inputs, continuous/final movement, undo/redo, numeric-zero ID and metadata roundtrip, style cancellation, Delete and undo, injected pointer cancellation and prior-disabled navigation restoration. The existing deletion-gate regressions separately cover confirmation guards. It checks 32 CSS-pixel projected height and precise tip across zoom 5/12/8, pitch 0/50/60/80 and bearing 0/31/85/150. Selection does not scale the mesh. It creates the same canonical renderer independently for read-only data, restores it after full style replacement and destroys it idempotently. A full style replacement during captured Pin drag rolls back and restores navigation; incremental replacement restores editor Pin resources. Native off-target pan preserves geometry and storage remains unchanged. The bundle run asserts exactly three Helper resources.

Terrain coverage uses real raster/DEM requests fulfilled with a generated constant 120m Mapbox-encoded tile, exaggeration 1.6, then compares the custom pin tip against MapLibre's public Marker positioning within 2 CSS pixels. DEM load and camera-target elevation are verified; no mocked elevation API. Screenshots show mesh depth/perspective at flat and tilted cameras, red recoloring, terrain and fresh emulated-touch movement. These are controlled library fixtures, not an owner's actual GPS/browser/cache session.

Compatibility checks: existing drawing regression; source/bundle immediate shapes, boundaries and three-asset contract; source/bundle legacy native drawing, clean edit switching, deletion gates, object sessions, pending base tiles and removal; cold offline object factory; bundle and registry contracts; icon regressions. Main and game JavaScript were regenerated because the shared icon catalog changed; unrelated CSS/inspection line-ending churn was restored. Runtime manifests retain scoped drawing CSS/shapes/ruler/scale revisions.

Failure history:

- Native color input scrolled the document. The old captured screen position then failed the mouse-drag assertion. The fixture now scrolls the map into view and recomputes the head coordinates after color input. Production drag logic was not changed for this failure.
- Terrain checks initially expected positive `queryTerrainElevation` at the camera center and timed out at zero, with screenshots/logs preserved. Inspection of the pinned 4.6 engine showed the public query subtracts camera-target elevation. The fixture now checks loaded DEM/positive target elevation. The renderer was also corrected to add public `getCameraTargetElevation`, so its world-space terrain tip is accurate rather than below terrain. The public native-marker comparison passes.
- Geographic-north orientation made a rotated pin excessively wide when height was normalized. The mesh now follows camera heading and responds partially toward upright with half the camera pitch, retaining genuine map-space depth/perspective and geographic-light shading response; subsequent screenshots and size checks use that implementation.
- A shell quoting attempt to edit the shader failed before changing a file; the source edit was applied through the patch tool.

Physical touch/Safari/AT and WebGL1 devices are not certified. The renderer includes public WebGL2/OES vertex-array paths. Selection accents stay inside the mesh; hit testing expands a rectangular screen target and does not issue a separate GPU occlusion query. Depth testing controls rendered terrain visibility. No application push/deployment or canonical publication occurs before independent exact-head review.
