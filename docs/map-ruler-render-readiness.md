# Ruler render readiness correction

Task 248 addresses a reproduced canonical 0.21.312 defect. With an initialized map style and four deliberately held raster requests, native clicks produced a fixed 2.04 km measurement while `map.isStyleLoaded()` stayed false. The style contained only the background/pending raster; no ruler source, line layer or endpoint layer existed. The original screenshot `output/playwright/ruler-pending-before.png` and reproduction harness/output are retained locally. This reproduces the owner's symptom; Developer task 247 must independently correlate the original served/cached app session before calling it that session's cause.

The old initial-install guard required all style sources to finish, with retries only at `idle`/`style.load`. A pending base source can prevent those retries indefinitely even though the style can accept new sources and layers. Tile-free tests exercised calculation and rendered geometry, but missed this readiness condition. Their passing results did not establish behavior while tiles remain unresolved.

The ruler now uses public style availability, matching the complete drawing adapter's established behavior. A hydration guard prevents reentrant installation. A coalesced `styledata` microtask repairs only missing owned source/layers, covering incremental replacement which need not emit `style.load`. Intact resources do not trigger repeated `setData`; a 100-event burst regression checks zero redundant writes and exactly two ruler layers. Null/unavailable styles defer installation and permit exit/destroy; full style replacement, terrain toggles and 2D/3D retain a completed pair. A continuous render/triggerRepaint loop also removes idle as a recovery dependency. No private engine state, app distance math, alternate component or modular fallback is introduced.

## Validation

`node tests/map.ruler.rendering.regression.mjs` uses real MapLibre, source and bundle, native mouse at 1200px and 375px widths/50° pitch/31° bearing. Raster and DEM tile requests remain held throughout the preview/fixed assertions and full/diff style replacements. Each assertion waits for a rendered dashed line and separately queries rendered endpoint features near both projected coordinates; a numeric result or source GeoJSON alone does not pass. Screenshots for preview/fixed/restored states are retained under `output/playwright/ruler-render-*` and inspected. A fresh touch-enabled Chromium context tests two native emulated taps while DEM requests remain pending. No physical-device touch/pinch claim.

The first bundle test exposed a fixture race by reading `getStyle().layers` during full replacement when style is temporarily absent. The wait now treats absent style as not ready, preserving line/both-endpoint assertions. That failed run is not counted as a pass. A dedicated initially-null-style case tests activation/exit, later style installation, unique resources and teardown. Existing ruler distance/guard/copy/lifecycle checks and cold exactly-three-Helper-asset loading remain required, alongside bundle and registry checks. Owned contexts, CLI sessions and static servers close after success or failure.
