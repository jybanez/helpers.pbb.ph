# Real DEM terrain anchoring correction

Developer message 10485 reported a settled native-reference discrepancy in renderer 315 (unchanged in main bundle 316). Reproduced using the application's real endpoint `https://mapserver.pbb.ph/tiles/terrain/{z}/{x}/{y}.png`, MapLibre 4.6, coordinate [123.88621598482132,10.315162060901429], zoom 17, pitch 50, bearing 85 and exaggeration 1.6. On a 1098px demo canvas the old tip was (549,143.6442) versus settled native Marker/project (549,229), with camera-target elevation 59.21640609466372 and relative query zero. This reproduces the reported approximately 81px discrepancy at the application's different canvas size.

Pinned engine inspection shows `customLayerMatrix` returns the Mercator matrix before camera-target elevation translation, while terrain projection applies that translation and `queryTerrainElevation` returns terrain elevation minus camera-target elevation. The renderer must use the relative query directly. Adding the public camera-target elevation caused the vertical offset. The corrected renderer uses only the public custom-layer matrix, MercatorCoordinate and relative query; it uses no private engine APIs or application workaround. The earlier documentation's absolute-elevation conversion was incorrect and is corrected.

Source and bundle tests wait for loaded terrain and positive camera-target elevation, then explicitly render 20 frames before reading the native 1px center Marker and Pin bounds. Initial corrected tip/reference match exactly at (549,229). Further checks cover camera zoom/pitch/bearing changes, terrain off/on and full/incremental style replacement, with 20 rendered frames per transition, within 2px tip tolerance and 0.5px height tolerance around 32 CSS px. Original native Pin source/bundle regression also passes, including mouse/touch altitude/metadata/history, constant DEM, read-only/style/lifecycle and three-asset loading. Bundle/registry contracts and 82 normalized artifact hashes pass.

The real terrain service returned HTTP 502 errors for several neighboring raster/DEM requests. Those errors are recorded separately from the loaded center's anchoring comparison; this is not a clean-network or complete-tile-coverage certification. No page JavaScript errors were observed. Screenshots `output/playwright/pin-real-terrain-source.png` and `pin-real-terrain-bundle.png` show the actual DEM raster background; the bundle image was inspected. Baseline failure log and browser console logs are retained. Physical device, original owner browser and application SW adoption remain unverified.

Main bundle, adapter import and Pin renderer revision 317; tools/icons/game 315 and package 0.21.83 remain. Only main JS dist content changes. No application edits, push or deployment. Independent review and merged-release verification precede adoption.
