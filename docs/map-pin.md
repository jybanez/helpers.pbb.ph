# Canonical 3D Pin

Color channels: existing Fill (`helperStyle.fill`) controls the rounded head RGBA and the inset's opacity. The circular inset face stays a neutral shaded detail; it has no separate color form. Existing Stroke (`helperStyle.stroke`) controls the raised inset rim/outline RGBA. Selection replaces that rim's color within the existing mesh without increasing the approximately 32 CSS px height.

Schema 1 can retain the Point discriminator without a migration: never infer Pin from legacy Point geometry alone. For combined saved-layer rendering, namespace renderer feature IDs across layers in a cloned view, retaining each original feature ID and unrelated metadata for edit/save. Give each renderer a unique owned layer ID. The host filters `isMapPin(feature)` out of its ordinary Point source/layer; the renderer only owns its custom layer and cannot modify host-owned circle layers.

Pin is distinct from Point: a GeoJSON `Feature` with `geometry.type: "Point"` and `properties.helperDrawingKind: "pin"`. Stable string and finite numeric IDs, including zero, and unrelated JSON metadata survive export/import, movement, history and color changes. Coordinates lie within Mercator latitude bounds. Plain Points keep their existing circular appearance. Pin adds no persistence; the host retains existing Save and authorization workflows.

The complete drawing toolbar supports `pin`. Put Pin immediately after Select and before Point; preserve Pan and all existing tools. The demo retains Pan before Select. Click/tap places a pin. Select its visible model to move it, including a larger touch hit area. The adapter uses its existing pointer capture, gesture locks, history, deletion confirmation and immediate/session edit semantics. Pin dragging preserves the initial pointer-to-tip offset and any third coordinate. Cancel rolls back; a completed release is one undoable edit and its click is suppressed. Fill color uses the existing `helperStyle.fill` RGBA contract and color transactions. Selection changes the inset rim color inside the same mesh; it never increases model size.

Rendering is actual self-contained WebGL triangle geometry: a rounded teardrop volume, tapered tip, recessed circular face, raised rim and face-normal shading. It uses the public MapLibre custom-layer matrix and `MercatorCoordinate`, not DOM/SVG markers or an application renderer. The mesh follows camera heading while retaining map-space depth and pitch response. Its projected height is normalized to approximately 32 CSS pixels each frame, independent of zoom and camera distance; projected width changes with perspective. Model tip is at its geographic coordinate, on the currently available terrain elevation. MapLibre 4.6's public `queryTerrainElevation` returns elevation relative to the camera target, matching the custom-layer matrix origin. The renderer uses that relative value directly; adding camera-target elevation would apply it twice. Missing terrain initially uses zero elevation and settles as terrain becomes available. The geographic distance/altitude of the model is deliberately not a real-world size. Screenspace targets are separate from model dimensions.

Saved read-only pins use `ui.map.pin` / `createMapPinRenderer(map, {maplibre, features, id, selectedFeatureId, visible})`. Existing MapLibre 4.6 is a prerequisite. `update(features, {selectedFeatureId, visible})` copies pin features, validates IDs/coordinates, updates colors/selection/visibility and requests a render; it does not mutate the input or install interaction listeners. Filter pin metadata out of the host's ordinary Point layer to avoid duplicate circles. `getBounds()` returns copied projected bounds and geographic-tip screen position for each rendered pin; `hitTest({x,y}, radius)` returns its string ID or null. Hidden renderers do not hit-test. Each renderer requires a unique layer ID.

The drawing adapter uses that same renderer and exposes `getPinBounds()`. Full/incremental style changes restore custom resources when a public style exists without waiting for base tiles or idle. Renderer destroy/removal frees owned GPU buffers/programs/VAOs and map listeners; destruction is idempotent. The host destroys its read-only instance on context changes. Source mode imports the canonical module; bundled mode includes it in the main bundle without modular fallback.

The renderer chooses the world copy nearest the camera when world copies are enabled. Bounds hit testing includes an expanded rectangular screen target; it does not perform a separate GPU occlusion query. Terrain visibility itself uses the map's depth buffer. Third coordinates are retained by editing/export; the displayed tip follows terrain rather than treating the third coordinate as a model height.

The model follows half the camera pitch toward upright to retain a legible teardrop near the horizon, while its actual volumetric geometry still responds to tilt. Light direction remains geographic, so bearing changes its shading. Omitted state fields in `update` retain the current selection and visibility.

Revision scope: main bundle, drawing adapter and pin renderer 317; drawing tools and icons 315; drawing CSS 311, shapes 309, ruler 314, scale 310. Game bundle changes because it includes the shared icon catalog; its revision is 315. Package remains 0.21.83. Existing editor guard, zero-ID and metadata protections remain in force.

Pin positions accept exactly two finite longitude/latitude values or a third finite altitude value. Altitude is retained as metadata through import, movement, color, history and export; display anchoring still follows terrain. Four-element positions and nonnumeric/nonfinite altitude are rejected atomically. Plain Points and other geometry retain their existing 2D validation.
